# Tópico: Integração e Gestão de Issues no GitHub
Descrição: Diretrizes de auto-melhoria autônoma, formato de issues e protocolo Human-in-the-Loop

- Ao propor novas issues no repositório, utilize sempre Conventional Commits no título em minúsculas (ex: `feat(tools): ...`, `fix(core): ...`, `refactor(memory): ...`).
- O corpo (`body`) da issue deve ser estruturado em Markdown com seções claras: `## Contexto & Motivação`, `## Requisitos Técnicos Sugeridos` e `## Critérios de Aceite`.
- Consulte o backlog atual com `list_github_issues` antes de formalizar propostas para evitar a abertura de tarefas repetidas ou já em andamento.
- Nunca acione `create_github_issue` sem confirmação expressa do usuário obtida em diálogo anterior (respeito irrestrito ao ciclo Human-in-the-Loop).
- A label `benito-sugestao` e a assinatura institucional no rodapé são anexadas automaticamente pelo sistema.
